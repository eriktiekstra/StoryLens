# Existing applications versus reusable components

Research date: 2026-10-15. Primary-source documentation/repository inspection; no applications installed or benchmarked. The component-level assessment is in [media ecosystem](media-ecosystem.md).

| Existing application | Verified relevant capability | Decision for StoryLens |
| --- | --- | --- |
| [Immich external libraries](https://immich.app/docs/features/libraries) | Recursively references existing photo/video directories; read-only volume mounts supported. Documentation warns that moving an external asset can lose application-owned metadata on rescan, and network filesystem watching may not work. [Smart Search](https://v1.116.2.archive.immich.app/docs/features/smart-search) documents image/text retrieval (archived version; not a guarantee about current defaults). | [INFERENCE] A good candidate when the actual need is a family photo/video library UI. Do not embed an entire asset-management server just to obtain a portable analysis engine. Preserve content-based identity and user feedback independently of paths here. |
| [PhotoPrism metadata](https://docs.photoprism.app/user-guide/library/metadata) | Indexes embedded EXIF/XMP/proprietary metadata and sidecars; can use ExifTool; reads external changes on reindex when modification dates change. [Content settings](https://docs.photoprism.app/user-guide/settings/library/) document previews, stacks and a quality-review filter. | [INFERENCE] Reuse mature metadata tools rather than PhotoPrism's application/database conventions. Its album/library experience may already solve discovery needs, but editorial time-aligned audio/video analysis is a different product boundary. Keep emotional relevance separate from technical quality and do not assume mtime alone proves unchanged content. |
| [FiftyOne](https://github.com/voxel51/fiftyone) / [documentation](https://docs.voxel51.com/) | Open-source visual-AI dataset curation, image/video browsing, labels, embeddings, near-duplicate discovery and evaluation. Repository identifies Apache-2.0 licensing; separate enterprise offerings exist. | [INFERENCE] Useful optional evaluation/curation environment for models and labeled fixtures. Not necessary infrastructure for end-user local indexing, durable stage cache or an editor-independent storyboard contract. Do not import its full application stack for M1. |

These comparisons do **not** establish that any application's complete feature set lacks a specific capability; no exhaustive competing-product audit was performed. None was verified as a drop-in implementation of the full requested engine. Decision: integrate lower-level FFmpeg/Pillow/ExifTool and capability-specific ML libraries; consider future optional import/export adapters for users who already own a library in another application. Do not duplicate their full web/mobile library UI.

Licenses must be checked at the exact source/artifact revision before code reuse. StoryLens does not copy code from these applications. MIT for original StoryLens code does not relicense a dependency or model. Claims above are tied to mutable official pages; there is no performance or runtime compatibility evidence.
