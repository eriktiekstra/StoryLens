# Security policy

## Current guarantees and limits

Default metadata/technical processing runs locally without inference/network requests. Explicit semantic analysis/search uses local CPU CLIP/SigLIP models; captions send bounded metadata-free RGB frames only to a numeric loopback Ollama origin. The adapter requires daemon cloud-disabled status, an installed local vision-capable model, pinned model digest/runtime version, and denies redirects/proxy environment routing. No automatic downloads, cloud fallback, credentials or telemetry are introduced. Trust the selected runtime/model and enforce OS egress restrictions for a stronger offline guarantee; a loopback daemon is not a sandbox.

Sources are read-only; no sidecars are written, and analysis lives separately in a local SQLite catalog/artifact tree. Catalogs/exports are not encrypted and can contain paths, GPS, model descriptions and embeddings. Restrict permissions and use encrypted disks as needed. Model captions are untrusted hypotheses and may hallucinate or contain prompt injection; never execute them as agent instructions.

FFmpeg/ffprobe run with argument arrays (no shell), a finite timeout and file/pipe protocols only. This blocks ordinary remote-protocol media references; **it is not a decoder sandbox or a universal no-network guarantee for arbitrary configured executables**. Configure only a trusted local ffprobe. Symlink entries are skipped, but a user-selected root is resolved; concurrent filesystem replacement and decoder bugs remain risks. Analyze untrusted media in an OS sandbox with read-only source mounts, restricted filesystem access, resource limits and network disabled. Metadata can be large or malformed. Pillow pixel limits remain enabled. Technical extraction bounds streamed/probe/error/JPEG payloads, source pixels, samples and scene count; metadata-only ffprobe capture is still not byte-capped. Derived scene JPEGs and signal results are sensitive too, stored in the local catalog-adjacent artifact tree.

The optional MCP server is stdio-only: no remote listener or HTTP API. Launch with explicit `--allow-root` directories; canonical path checks reject traversal and symlink escapes, catalog queries are filtered to authorized media, and MCP output is bounded. Event/feedback tools filter unapproved media before grouping and fail closed when a manual relationship spans approved and unapproved sources. These are application checks, not an OS sandbox or protection against concurrent filesystem replacement. CLI synchronous path access follows normal OS permissions. Durable workers outlive the transport, store private state beside the catalog, and respond to persisted cancellation at stage boundaries; protect the local job database as you protect the catalog. Do not expose the server to untrusted clients or grant unrestricted home-directory roots.

Recommendations use stored evidence unless query text explicitly opts into the configured local encoder. Portable storyboards contain source IDs/times and untrusted rationale/title text, not source paths or transcript words. Validation enforces current approved-root visibility, timing and user constraints but does not rehash indexed sources or grant an editor permission to mutate them. MCP storyboards are returned whole or rejected for size, never silently truncated into an incomplete edit plan.

FilmCraft editing is external to StoryLens. The optional handoff prepares a StoryLens MCP configuration and copied instructions for an existing trusted agent host. That host owns all FilmCraft MCP calls and may have other filesystem/network tools. The prompt's original-media inspection permission is not access control and never authorizes cloud/provider disclosure. Configure only trusted hosts and separately approve disclosure of paths, metadata, transcripts, frames or media.

M9 benchmark workspaces and generated-fixture outputs must be new; benchmarks never reuse the configured user catalog or enable configured model inference. Reports/profiles contain private paths/errors and environment versions, so keep them local. Batch admission validates all roots before records/launches, but workers remain one process per queued job; the 32-root request bound is not a global resource quota. CUDA admission uses a private OS file lock shared only by cooperating same-user/cache processes, not GPU isolation or health detection. Do not unlink a live resource lock.

The optional Docker recipe does not publish an image. Run it unprivileged with read-only media/root filesystem, a separate writable local state directory and explicit egress/resource limits. Container exit also terminates its detached workers. Built images include native Debian packages with their own licensing/security obligations; the base digest and direct versions are not a complete transitive/apt lock. Release/license reports inventory evidence and unknowns, not legal clearance or vulnerability certification.

Both wizards default to basic analysis in a separate private project catalog, not the ambient/global library. Local AI can be enabled later with explicit settings and reusable model profiles. Saving settings or opening setup never starts inference. Optional sample inference is explicit, read-only, isolated and bounded; ordinary analysis cancellation is cooperative at safe checkpoints, not an immediate native-runtime kill. Saved project/config files can select trusted executables and local models: open only trusted local projects. Terminal output neutralizes control/ANSI characters; browser output uses text DOM nodes rather than injecting model/path HTML.

Recommended-model downloads are a separate consent-required action. Only allowlisted model repositories or the checked numeric-loopback Ollama runtime are used; no private source paths/media are included. Downloads may contact external model hosts, may consume substantial disk/bandwidth, and are not offline analysis. Python packages are never installed automatically. Model/profile storage must not use symlinks; profiles contain only allowlisted model settings. Sample/model/runtime code is trusted local software, not an OS sandbox.

The browser wizard runs a loopback-only HTTP listener with a random session token, exact Host checks and mutation Origin checks. Its private URL is printed/opened locally; do not forward it, expose it through a proxy, or publish its token. Authenticated local directory browsing follows the OS user's permissions; possession of the token therefore grants access to sensitive directory names. The UI is separate from MCP's stdio transport and is not a public/LAN service. Diagnostic reports remain local and contain sensitive paths/errors; review before sharing.

## Future cloud policy

No cloud adapter is shipped. A future adapter must enforce explicit provider/task/data-class authorization, deny uploads by default, minimize frames, document retention/provider terms and never include credentials in logs/exports. Model acquisition is a separate deliberate permission. The current Ollama adapter requires OLLAMA_NO_CLOUD=1 (or equivalent daemon setting), verified via /api/status; missing/false status and remote/cloud model routing are rejected. This protects the application policy, not a malicious/reconfigured daemon or arbitrary executable. See integration setup and research notes.

## Reporting vulnerabilities

This new repository has no established private security address or supported-release policy yet. Use the hosting repository's private vulnerability reporting if enabled; otherwise contact a maintainer privately before providing exploit material. Do not upload family media, GPS, credentials or weaponized files to public issues. Public reports may describe the affected version and sanitized impact without private payloads. No response-time guarantee is claimed.
